📖 About the Project

The Transformers: Forged to Fight — Revival Project is an independent fan-driven technical project focused on exploring ways to preserve and restore aspects of Transformers: Forged to Fight, a mobile fighting game featuring characters from the Transformers universe.

The project aims to investigate Android compatibility, offline functionality, build tooling, and community-driven technical development.

The goal is to encourage learning, experimentation, and collaboration while documenting progress and technical discoveries for other interested fans and developers.

This is an independent initiative and is not an official continuation of the original game's development.

🎯 Project Goals

The project aims to explore the following areas:

- Game preservation: Investigate ways to preserve access to game functionality where technically and legally possible.
- Offline functionality: Explore which game features can operate without an active internet connection.
- Android development: Use Android development tools and build systems to investigate application behavior and compatibility.
- Build automation: Develop a reproducible build workflow using GitHub and compatible cloud-based tools.
- Technical research: Document findings, compatibility issues, build errors, and potential solutions.
- Community collaboration: Encourage respectful technical discussion, testing, documentation, and contributions.
- Long-term preservation: Record useful technical information so that progress can continue over time.

These are project goals, not a claim that every feature has already been implemented.

📱 Development Platform

Development currently focuses on Android and GitHub-based tools.

The project may involve:

- Android application build configuration.
- Gradle and Kotlin build tooling.
- APK packaging and build verification.
- Android compatibility testing.
- Build troubleshooting and documentation.
- GitHub-based collaboration and automation.

Development status and supported Android versions may change as testing progresses.

🧪 Testing and Compatibility

Testing is an important part of this project.

Where appropriate, testing may cover:

- Application launch and stability.
- Android compatibility.
- Build success and APK integrity.
- Offline behavior of supported features.
- Reproducibility of the build process.
- Errors, limitations, and regression issues.

Results will be documented as testing progresses. Compatibility with a particular device, Android version, or game version should not be assumed unless it has been verified.

🤝 Contributions

Contributions, technical discussions, bug reports, and documentation improvements are welcome, provided they respect the applicable licenses, intellectual property rights, and permissions.

Potential areas for contribution include:

- Android build configuration.
- Gradle troubleshooting.
- Documentation and setup instructions.
- Compatibility reports.
- Reproducible testing.
- General software engineering and preservation research.

When reporting an issue, please include the relevant error message, Android version, game version where applicable, and the steps needed to reproduce the problem. Avoid posting personal information, private credentials, signing keys, or other sensitive data.

🐛 Bug Reports and Suggestions

If you discover a problem or have a suggestion, provide a clear description of:

1. What you expected to happen.
2. What actually happened.
3. The steps required to reproduce the issue.
4. Relevant device, Android, and build information.
5. Logs or screenshots, with private information removed.

Please distinguish confirmed results from assumptions so that other contributors can investigate accurately.

🔐 Security and Responsible Development

Security and responsible handling of software are important.

- Never commit passwords, access tokens, private signing keys, or credentials.
- Do not publish another person's private code or confidential development materials without permission.
- Use software, game assets, and services only in ways that you are authorized to use.
- Report security concerns responsibly rather than publishing sensitive exploit details.
- Respect the rights of the original developers and other contributors.
